## 5. 上游更新如何进入二改

### 自动方式

进入 GitHub Fork 的 Actions 页面，运行 `Sync upstream changes`。工作流每天也会自动运行。

工作流的预期结果：

```text
官方 main 有更新
    ↓
Fork main 更新
    ↓
sync/upstream-main 生成
    ↓
创建 PR：sync/upstream-main → custom
```

用户需要检查 PR 的代码差异并运行适用测试，再合并 PR。

### 手动方式

工作区干净时：

```bash
git fetch upstream main
git checkout main
git pull --ff-only upstream main
git push origin main
git checkout custom
git merge --no-edit main
```

遇到冲突时不要强制覆盖。先停止，读取冲突双方，保留二改意图并适配上游变化，然后验证后再提交。

## 6. 当前项目重要事实

根 `pubspec.yaml` 显示：

- Dart SDK 约束为 `^3.11.0`；
- README 要求 Flutter stable `3.41+`、Dart `3.11+`；
- 项目使用 Riverpod、GetIt/Injectable、GoRouter 等；
- 存在大量 `packages/*` 本地包；
- 存在媒体播放、数据库、平台插件和多个 dependency override；
- `media_kit`、Windows WebView 等部分依赖有明确的补丁/版本原因，升级前必须阅读 `pubspec.yaml` 注释和 `patches/`。

源码定位建议：

```text
lib/       应用、认证、数据、播放、UI、服务和本地化
packages/  可复用本地包及服务器/播放核心
android/   Android 与 Android TV
windows/   Windows 原生壳和插件
web/       Web 资源和入口
test/      Dart/Flutter 测试
```
